# 通用工作流：采集 → 定位裁切 → 单图判断 → 可观测性

这是可复用方法，不是用户真实部署的副本。接口以仓库 runtime 为准；方法说明不表示任何具体部署已经验收。采集质量、模型效果、进程托管与监控接入必须分别验证。

## 1. 采集与授权

- 确认有权使用该摄像头与图像；只在用户指定的运行机器从其私有 go2rtc/RTSP 源抽帧，使用受信网络与访问控制。源地址、凭据、采样清单在 Git 外。
- 按预定义间隔/事件采样，保留原始来源与实际取帧语义；无录像、取帧失败就是缺失，不拿邻近时间冒充。RTSP 初始 H.265 P 帧可能缺参考而生成可打开的灰 JPEG；实时 capture 已在输入 `-i` 前设置 `-skip_frame nokey`，在既有超时内等待解码器关键帧，不再直接采用首个 inter frame。FFmpeg exit0 和 JPEG 可解码仍不证明所有图像内容正常，应复核实际画面；不引入固定 sleep、std 阈值或旧图替代。
- 视频解码、真实图像处理和模型请求留在获授权机器。用于本项目的运行/测试主机与代码编辑主机分离；Linux 不运行真实模型/图像测试。
- 明确保留期、磁盘配额、访问权限和备份/删除责任。不要采集与任务无关的私密区域；家庭原图、任何可还原图像的 base64/压缩包都不是测试夹具。

## 2. 标注和分组

定义目标语义：crib 外包框不是床垫 mask、婴儿框或可见性证明。独立标注并记录遮挡、不可评分、其他相似家具及负样本；模型输出不静默当真值。收集多个独立移动/光照事件，而不是把同一事件的相邻帧视为许多独立样本。

依据用户提供的事件/会话/时间段分组，显式 train/val/test/challenge/quarantine，边界留缓冲。组内绝不随机拆近重复。先冻结标注/参数，再训练；`audit_groups.py` 只能检查字段一致性，人工负责真实分组与 YAML 对应关系。

## 3. 训练与独立验证

参阅 [TRAINING.md](TRAINING.md)：固定环境、CPU 默认、先 train/val smoke，再从官方权重正式微调；val 选 checkpoint 和阈值，第一次 test 前冻结。test/challenge 的失败不触发现场降阈值或改 GT，新的迭代需要新独立事件。

可评分/不可评分分母分开，漏检真实保留。对实际 top1 bbox 与 padding 后 crop 进行独立视觉复核：目标是否正确、孩子原本可见区域是否完整、遮挡是否被误解为观察成功。高召回/高置信度不等于婴儿安全或持续可见。

## 4. 实时 YOLO crop + Qwen

通用链路：用户私有 go2rtc → 运行机 RTSP TCP 关键帧单图 → YOLO detection → 最高 confidence 目标框 → padding/floor/ceil/clip → 单张 JPEG crop → 用户配置的可信本地 Qwen 兼容端点。

- 60 秒周期、串行、不重叠，不追赶积压 tick；超时/跳 tick 的缺口必须可见。关键帧等待属于 capture 耗时，受 capture 超时限制；超时后标记失败并在下一周期继续，不无限等待。
- YOLO26 固定 OTM + NMS、模型/包/线程显式配置。图像尺寸、IoU/max_det/conf/padding 不是所有房间通用最佳值，部署前用冻结验证协议选择。
- 无框/检测失败/取帧失败记 `missing`、重置滤波，不调用 Qwen、不回退到旧静态 ROI；不能用上一帧 bbox 或 GT 偷补。
- 每个 Qwen 请求仅含一张当次实际 crop，无参考图。端点只来自用户私有配置，不自动云回退。远程地址意味着画面离开运行机，必须单独授权。
- `yes/no/unclear` 原始值和最近三次因果多数决分开；unclear 不投票、票不足/平票保留、首次明确初始化；missing 重置。**保持的 filtered 值不能当成本次观察成功。**
- 私有逐帧记录应包含采样/完成时间、raw/filtered、错误/缺失原因、bbox/crop/缩放尺寸、实际发送图 hash 与阶段耗时。单次结果和训练置信度都不能用来推断睡眠。

不得从本文生成可直接运行的家庭 RTSP/模型/PM2 配置，不复制用户部署脚本。

## 5. PM2 运维

PM2 管理业务 Python；单独 PM2_HOME、解释器、代码 release、配置、日志和输出路径。不要全局 `pm2 save/delete/restart`，不要影响同机其它应用。配置和 PM2 dump 也可能含环境变量/凭据，全部留在 Git 外。

Windows 的 PM2 named pipe 隔离受实际版本影响，不能只设置 HOME 就宣称隔离。参照仓库 `runtime/pm2-windows-isolation.cjs` 和 README 的版本约束，逐个 CLI/daemon 核验隔离；本文不复制私有启动脚本。若用开机任务，只引导专用 PM2 的 resurrect，不直接绕开 PM2 跑 Python。

变更前备份旧任务、完整触发器、配置和代码版本。有限前台三个真实分钟周期通过后，才按授权切换；旧任务只停用并保留回滚。SSH 启动 ack 不等于退出会话后存活；重新连接检查新样本/心跳/HTTP。进程崩溃恢复、系统重启自启分别实测；未测就明确列未验证，不把普通进程在线当成开机验收。

所有 runtime/训练测试只在指定主机的隔离环境执行，不安装或修改生产依赖。远程执行遵循本地安全操作规范、SSH 主机密钥校验与权限边界；本项目不提供机器专属脚本。

## 6. Prometheus 与 Grafana

只暴露低基数数字指标，不给图片、文件、配置或模型响应提供 HTTP 路由。仅在受信接口监听，以防火墙源地址 allowlist 加 HTTP allowlist 纵深限制；不加公网入口。真实 Prometheus target、Grafana datasource UID、登录和地址由所有者私有配置。

Grafana 包含 raw/filtered、时间线、新鲜度、worker 与 scrape up、ROI/置信度、阶段耗时、每类结果增量。必须同时看缺失/unknown、技术成功/业务结果和数据年龄。Prometheus/Grafana 自身也含家庭作息信号，不能无保护对外开放。通用查询见 [MONITORING.md](MONITORING.md)。

## 7. 发布前验收

发布前：核对实际采集和最终 runtime/指标契约 → 目标机 mock 与真实 smoke → 依赖/权重许可证审查 → 全部 Git 可达对象与历史审计 → 无敏感文件的干净 archive 审查 → 所有者确认公开 diff 后才 push。部署未验收时不要用通用文档冒称生产已就绪。

.gitignore 不处理已跟踪文件与历史；删除当前文件也不清洗历史。没有审计过的旧提交不能因为当前树干净就放行。公开只包含通用原创代码/文档与合成素材；用户照片、标签、训练后权重、真实 manifest/hash/时间/运行配置一律不在范围内。
